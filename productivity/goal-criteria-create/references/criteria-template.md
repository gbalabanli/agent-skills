# Acceptance Criteria Template

Use this template when writing `acceptance-criteria.md`.

```markdown
# Acceptance Criteria

> Generated by goal-criteria-create on YYYY-MM-DD
> Source: <description of what was analyzed — task, plan file, spec, etc.>

## Summary

| Metric | Value |
|--------|-------|
| Total criteria | <N> |
| P0 (blocker) | <N> |
| P1 (must-have) | <N> |
| P2 (should-have) | <N> |
| P3 (nice-to-have) | <N> |
| Verification: test | <N> |
| Verification: check | <N> |
| Verification: manual | <N> |
| Verification: subagent | <N> |

## /goal Condition

```
<ready-to-paste /goal condition string>
```

## Criteria

### Functional

- [ ] C1: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)
- [ ] C2: ...

### Integration

- [ ] C<N>: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)

### Non-functional

- [ ] C<N>: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)

### Edge Cases

- [ ] C<N>: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)

### Regression

- [ ] C<N>: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)

## Verification Commands

Run these commands to verify code-based criteria:

```bash
# Tests
<command 1>
<command 2>

# Static checks
<command 3>
```

## Manual Verification Steps

Follow these steps for manual criteria:

1. <Step 1 — what to do>
2. <Step 2 — what to observe>
3. <Expected result>

## Subagent Verification

For criteria delegated to subagents:

- **C<N>**: Spawn an explore subagent with: "<instructions>"
- **C<N>**: Spawn a general subagent with: "<instructions>"

## Notes

- <Any assumptions, open questions, or caveats>
```

## Template Rules

- Omit any category section that has no criteria (e.g., if no edge cases, remove the section)
- The `/goal` condition block uses triple backticks to show it as a copyable code block
- Verification commands are grouped by type (tests first, then checks)
- Manual steps are numbered and describe both the action and the expected observation
- Subagent instructions are specific enough for a fresh subagent to verify without additional context
- Notes section captures assumptions and open questions, not implementation details
