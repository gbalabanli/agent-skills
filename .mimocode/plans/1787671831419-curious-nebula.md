# Plan: Create `hand-off-to-new-session` Skill

## Goal

Create a new MiMoCode skill that generates a consolidated `HANDOFF.md` at the project root, giving a fresh session (or different CLI tool) full context about what happened in the current session — without re-reading the full conversation.

```
    └── handoff-template.md         # HANDOFF.md template structure
```

Placed in `.mimocode/skills/` (MiMoCode-native location) with `category: productivity` metadata, matching the convention used by `goal-criteria-create`.

## Files to Create

### 1. `SKILL.md` — Main skill file

**Frontmatter:**
- `name`: `hand-off-to-new-session`
- `description`: Trigger phrases: "hand off", "handoff", "new session context", "export session", "transfer context", "wrap up session", "session summary", "prepare for next session", "create handoff doc". Negative: not for general memory management or checkpoint writing.
- `metadata.category`: `productivity`
- `metadata.tags`: `[session, handoff, context-transfer, productivity]`

**Body structure (10-step workflow):**

| Step | What | Tools | Parallelizable |
|------|------|-------|----------------|
| 1 | Locate session data (session ID, paths) | `memory` search | — |
| 2 | Read checkpoint.md (all 11 sections) | `read` | Yes (with 3-8) |
| 3 | Read project MEMORY.md | `read` | Yes |
| 4 | Find + read task progress files | `glob` + `read` | Yes |
| 5 | Read session notes (notes.md) | `read` | Yes |
| 6 | Read session diffs JSON | `read` | Yes |
| 7 | Capture git state (status, diff, log) | `bash` x3 | Yes |
| 8 | Search conversation for key decisions | `history` x2 | Yes |
| 9 | Write HANDOFF.md | `write` | No (depends on all above) |
| 10 | Confirm to user | direct output | No |

Steps 2-8 are all reads and can run in parallel for speed.

**Data source mapping (checkpoint → HANDOFF):**
- §1 Active intent → §1 Quick-start (verbatim quote)
- §2 Next action → §6 Next steps
- §3 Directives → §2 Project context
- §4 Task tree → §5 Current state
- §5 Current work → §3 Session summary
- §6 Files → §4 Changes made
- §7 Discovered knowledge → §9 Discoveries
- §8 Errors → §8 Errors/fixes
- §9 Live resources → §5 Current state
- §10 Design decisions → §7 Key decisions
- §11 Open notes → §6 Next steps

**Fallbacks for missing data:**
- No checkpoint.md → reconstruct from `history` tool
- No MEMORY.md → use `memory` search
- No session_diff → use `git diff --stat`
- No task files → use checkpoint §4
- No git repo → skip git steps

### 2. `references/handoff-template.md` — Template file

9-section HANDOFF.md template:

1. **Quick-start** — User's goal (verbatim), TL;DR (2-3 sentences)
2. **Project context** — Name, workspace path, branch, rules, directives
3. **Session summary** — Chronological action table + commits
4. **Changes made** — File table (path, action, rationale)
5. **Current state** — Task status, uncommitted changes, running processes, files in flight
6. **Next steps** — Actionable numbered list + unresolved questions
7. **Key decisions** — Decision table (decision, rationale, alternatives rejected)
8. **Errors and fixes** — Error table (error, fix, recurrence risk)
9. **Discoveries** — Bullet list + candidates for MEMORY.md promotion

## Output Principles

1. Key decisions summarized (1-2 sentences), not raw message dumps
2. Next steps are concrete enough for a new agent to execute immediately
3. File paths are absolute
4. Document is timestamped with session ID
5. Verbatim user quotes preserved for intent/directives
6. Empty sections show "(none)", never left blank
