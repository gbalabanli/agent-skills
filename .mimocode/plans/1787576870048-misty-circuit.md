# Plan: Create `goal-criteria-create` Skill

## Goal

Create a new MiMoCode skill that generates structured acceptance criteria with verification methods and a ready-to-paste `/goal` stop condition. Works as a companion to MiMoCode's built-in `/goal` command.

## Files to Create (3 files x 2 locations = 6 writes)

### 1. `SKILL.md` — Main skill file

**Frontmatter**: name `goal-criteria-create`, description with trigger phrases ("create acceptance criteria", "define criteria", "goal criteria", "what does done look like", "define done", "create a /goal condition").

**Body** — 7-step workflow:

| Step | What it does |
|------|-------------|
| 1. Gather Context | Read task/plan/spec/codebase signals (test framework, linter, CI config). Ask 1-2 clarifying questions only if scope is ambiguous. |
| 2. Identify Work Items | Extract discrete items, group into 5 categories: Functional, Integration, Non-functional, Edge Cases, Regression. |
| 3. Write Acceptance Criteria | Format: `- [ ] C<N>: <observable outcome> — verify: <method> (priority: P<N>, covers: <source>)`. Every criterion must be falsifiable and independently verifiable. |
| 4. Assign Verification Methods | Decision tree: test → check → manual → subagent. Each criterion gets one primary method (optional secondary). |
| 5. Synthesize `/goal` Condition | Distill all criteria into a single <300 word natural-language string. Template: "All acceptance criteria in acceptance-criteria.md are satisfied. Tests pass: <cmds>. Checks pass: <cmds>. <N> manual checks confirmed: <summary>. No P0/P1 criteria remain unchecked." |
| 6. Write Output File | Write `acceptance-criteria.md` using the template. Display `/goal` command as ready-to-paste. Show summary table. |
| 7. Update When Work Changes | Re-read existing file, update only affected criteria, re-synthesize `/goal` condition. |

Priority model: P0 (blocker), P1 (must ship), P2 (should ship), P3 (nice to have). Guideline: 0-1 P0, 2-4 P1, rest P2/P3.

### 2. `references/criteria-template.md` — Output template

Sections:
- **Header**: generation date, source description
- **Summary table**: total criteria, breakdown by priority and verification type
- **`/goal` Condition**: ready-to-paste code block
- **Criteria by category**: Functional, Integration, Non-functional, Edge Cases, Regression (omit empty sections)
- **Verification Commands**: grouped bash commands for test/check methods
- **Manual Verification Steps**: numbered steps with action + expected observation
- **Subagent Verification**: per-criterion subagent instructions
- **Notes**: assumptions, open questions

### 3. `references/verification-methods.md` — Method catalog

Four method types:

| Method | When to use | Example |
|--------|------------|---------|
| `test:<cmd>` | Behavior has automated test | `test:npm test auth.test.js` |
| `check:<cmd>` | Code quality / type safety / build | `check:npx tsc --noEmit` |
| `manual:<steps>` | UI/UX, visual, interactive | `manual:navigate to /login → redirects to /dashboard` |
| `subagent:<instructions>` | Multi-file code tracing, exploratory | `subagent:explore: "Read src/auth/ and confirm error handling"` |

Includes decision tree for method selection and rules for combining primary + secondary methods.

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| P0-P3 priority model | Borrowed from review-agent; enables `/goal` to gate on "no P0/P1 unchecked" |
| 5 criteria categories | Covers full spectrum from user-requested to implicit regression |
| Criterion format `C<N>: outcome — verify: method (priority, covers)` | Compact, parseable, traceable; mirrors compose-next's task format |
| `/goal` as single string <300 words | Matches MiMoCode's `/goal <condition>` interface; judge model evaluates natural language |
| Progressive disclosure (SKILL.md body + references/) | Keeps SKILL.md under 500 lines; heavy templates in references loaded on demand |
| Update-in-place (Step 7) | Avoids regenerating entire file on changes; preserves stable criterion IDs |
